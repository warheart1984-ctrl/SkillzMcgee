## Statement

**Transformation Provenance Completeness (Invariant P-1):** Every semantic transformation SHALL declare its authority, specification, implementation, assumptions, input artifact, output artifact, and receipt.

## Normative text

For each transformation T in the constitutional loop:

1. `authority_id` — active governance authority at execution time
2. `transformation_spec_id` — binding transformation contract (SpecificationID)
3. `implementation_id` — code module claiming conformance (ImplementationID)
4. `assumptions` — policy version, evaluation mode, constitution version, frame set version (when applicable)
5. `input_artifact_id` — exactly one input (CA-1.0)
6. `output_artifact_id` — exactly one output (CA-1.0)
7. `receipt_id` — governance receipt (REC-HDR-1.0)

All seven bindings MUST appear in the provenance ledger entry (PL-1.1).
