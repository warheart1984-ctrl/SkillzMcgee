## 1. Purpose

This brief defines the transition from Version 1.0 (frozen semantics) to Version 1.1 (capability expansion).

---

## 2. What Carries Forward

The following remain frozen:

- semantics
- invariants
- canonical categories
- constitutional loop
- proof graph semantics
- evidence and provenance model
- compatibility rules
- stability principle
- amendment procedure

These define the identity of the platform.

---

## 3. What Can Evolve in 1.1

Version 1.1 may introduce:

- new operator tools
- new drift analytics
- new modeling templates
- new visualizers
- new conformance profiles
- new workflow presets
- new analysis heuristics
- performance improvements
- observability enhancements

All without touching semantics.

---

## 4. What Must Not Change

Version 1.1 must **not**:

- modify CAR-1.0
- alter invariants
- change the constitutional loop
- redefine categories
- weaken reproducibility
- alter proof graph semantics

Any such change requires Version 2.0.

---

## 5. Versioning Discipline

| Version | Qualifies when |
|---------|----------------|
| **1.1** | Expands capability without altering semantics |
| **2.0** | Alters semantics, invariants, or constitutional guarantees |

---

## 6. The Purpose of 1.1

Version 1.1 exists to:

- improve usability
- expand capability
- enhance operator experience
- strengthen conformance
- enrich modeling
- increase adoption

without destabilizing the constitutional foundation.
