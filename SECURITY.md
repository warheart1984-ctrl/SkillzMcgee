# Security Policy

## Reporting Vulnerabilities

If you discover a security vulnerability in SkillzMcGee, please report it responsibly.

**Do NOT** open a public issue for security vulnerabilities.

Instead, please send an email to: security@example.com

Include:
- A description of the vulnerability
- Steps to reproduce the issue
- Any potential impact or exploit scenarios

## Supported Versions

| Version | Supported |
|---------|-----------|
| Latest | ✅ |

## Security Principles

SkillzMcGee is designed with governance and continuity at its core:

1. **Continuity Ledger**: All operations are recorded in an immutable ledger
2. **State Continuity**: State is maintained across operations with proper validation
3. **Governance**: All actions are governed by constitutional principles
4. **Reality Stack**: Adheres to the reality stack architecture for consistency

## Known Security Considerations

- **Node Identity**: Node identity files should be kept secure and not committed
- **Environment Variables**: Sensitive configuration should use environment variables
- **Ledger Integrity**: The continuity ledger should be protected from tampering

## Dependency Security

We regularly update dependencies to address known vulnerabilities. CI includes automated dependency scanning where available.
