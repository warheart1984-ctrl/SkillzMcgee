# Claim Status Registry (CSR-1.0)

**Authority:** CRK-1 Conformance v1.0  
**Status:** Normative  
**Registry:** [registry.json](./registry.json)  
**Invariant:** **PI-1** ([CRK1-R044](../../specification/normative-requirements/R044.md))

## Purpose

Ensure every constitutional claim is explicitly classified. There is **no undocumented middle ground**.

## Progression model

```
Normative → Implemented → Verified → Reproduced
                              ↘
                            Research (explicit opt-out of v1.0 guarantees)
```

| Status | Meaning | Requirements |
|--------|---------|--------------|
| **normative** | Required by specification only | Catalog entry + traceability row |
| **implemented** | Demonstrated by at least one implementation | Transformation record or MRI path + partial tests |
| **verified** | Validated by conformance ecosystem | Evidence + receipt + anchored provenance + CTS/repo tests |
| **reproduced** | Independently confirmed | R1-0 reproduction log + matching hashes |
| **research** | Outside Version 1.0 guarantees | Documented in release notes; never presented as verified |

## CSR-1.0 structure

```json
{
  "claims": {
    "CRK1-R001": "implemented",
    "CRK1-R002": "implemented",
    "CRK1-R003": "normative",
    "CRK1-R004": "research",
    "CRK1-R012": "verified"
  },
  "metadata": {
    "generated_at": "<ISO8601>",
    "commit": "<hash>",
    "version": "CSR-1.0"
  }
}
```

## Rules

1. Every normative requirement (R001–R044) **must** appear in `claims`.
2. No claim may be unclassified.
3. **Verified** requires: evidence, receipt, anchored provenance, and passing verification (CTS or repo test).
4. **Reproduced** requires: independent R1-0 reproduction with matching Merkle roots / drift envelopes.
5. **Research** requires: explicit documentation in [RELEASE_NOTES_v1.0](../../../meta/RELEASE_NOTES_v1.0.md) or requirement notes.
6. CSR is regenerated by `crk cor generate --refresh-csr` but committed registry is the audit baseline.

## Regeneration

```bash
node tools/generators/csr-registry.mjs
node tools/crk.mjs cor generate --refresh-csr --out meta/COR-1.0.json
```

## COR integration

COR-1.0 reads CSR-1.0 and **cross-checks** each claim against derived dimensions. Mismatches appear in `exceptions` (e.g. CSR says `verified` but provenance is `missing`).
